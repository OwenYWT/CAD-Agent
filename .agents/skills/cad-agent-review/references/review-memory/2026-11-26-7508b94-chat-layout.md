# 会话中的原生视口与候选审阅

Codex，审查编号 `chat-layout`，2026-11-26。基线为 `7508b94d9f4e1cf0a306508d66ab27729db2a18e`，对照为本地 `ui/focused-workspace` 工作树。范围涉及 EngineeringWorkspace、MechanicalWorkspace、TaskCard、ChangeSetDialog、sessionStore、ProjectStart 和 ProjectSidebar。涉及 02、03、04、05、06、08、10、14、15、16 域。复核阶段只记录证据。

- 布局展开或收起必须保留同一原生渲染器、已选特征、相机及 LOD。用同一保存模型从对话到全屏、属性、再回到对话，比较 DOM 画布实例及调整相机后的像素。七种宽度都观察到稳定身份。可复查 `workspace_layout_browser.py` 与 `browser_contract.py`。
- 文档已有保存版本时，任务处于候选和当前视口展示已保存版本可以同时成立。应实际点击“预览候选变更”，独立核对当前视口的修订 ID 和任务的待审修订 ID。浏览器查看、折叠或预填审阅意见均不应推进分支。审阅和提交的真实回执、状态版本以及原文件哈希才证明保存。
- WebSocket 结果和随后重放的快照可能对应同一句助手回复。除了消息数量，还要验证可编辑源码和文件结果保留，且重复快照不产生新提交。前端 task-state 测试覆盖不同到达顺序。
- 自然语言修改时，两套布局可发出相同的业务字段，模型仍可能给出不同规划。真实服务拒掉越界计划、候选数为零，与最终有证据的成功应分别记录。保留任务 ID、基线修订、选择、输入、文件哈希及独立 FreeCAD 测量结果使差异可核验。

证据等级涵盖 CONTRACT_ONLY、PASS 与 REAL_ACCEPTANCE。外部短信、第三方 CAD 生产账户、实机和其他条件门的边界见报告。此次没有改写稳定功能地图或历史记录。[完整审查及证据](../../../../../docs/qa/code-review/2026-11-26-7508b94-chat-layout.md)
