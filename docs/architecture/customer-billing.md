# 租户隔离与套餐基础

客户计费模块为 M12，数据库迁移为 `0033_tenant_billing_foundation`。本阶段提供真实的套餐、订阅、月调用额度、余额和审计流水，尚未接入在线支付、自动续费或按价格扣费。管理操作不代表收到支付平台款项。

## 隔离边界

登录身份映射到稳定的个人 tenant / principal。客户端不能通过填写 tenant ID 获得权限；共享工作区必须先通过已有的有效成员校验。模型、文档、任务、历史和文件继续使用原有项目授权、PostgreSQL 强制 RLS 与对象下载授权。数据库连接用事务级租户上下文，避免连接池复用残留上一用户的身份。

新增订阅、钱包、流水和套餐变更事件均启用强制 RLS。工作区的普通项目成员可以协作建模，但不能读取工作区余额和流水；只有工作区 owner / admin 可以读取。平台管理员才可以配置套餐或调账。普通运行角色只能初始化默认套餐及零余额账户，不能直接 UPDATE 余额、升级套餐或 INSERT 余额流水。全局套餐目录不包含客户数据。

模型 WebSocket 每条消息、任务事件 WebSocket 每轮推送重新检查登录令牌。退出或刷新登录后，旧连接关闭，不再接受旧会话操作或继续推送任务详情。前端刷新令牌后主动替换建模与任务连接，避免下一次请求发往旧连接。已经受理的持久工作流继续运行，其后续读取仍须重新鉴权。

## 三档套餐

| code | 初始名称 | 初始状态 |
| --- | --- | --- |
| basic | 基础版 | v1 已发布，沿用原有系统额度，无新增收费 |
| pro | 专业版 | v1 草稿，价格和月额度待确定 |
| team | 团队版 | v1 草稿，价格和月额度待确定 |

“团队版”当前只是第三档套餐名称，不会自动创建组织、授权席位或开放跨用户数据。组织和协作仍由已有显式成员权限控制。

新版本发布前必须提供人民币分为单位的月标价及月模型请求额度。版本一经创建不能修改或删除；变更需新建版本。订阅绑定具体版本，管理员以 revision 乐观锁和幂等键显式分配，不能通过自助接口购买未发布档位。标价仅保存运营配置，目前没有自动扣款、按比例退款或自动续费。

已有个人 / 组织账户迁移为基础版和零余额；新账户首次读取或模型准入时事务性初始化。原有 provider 预算、模型数据、已用量和预留均不重置。

## 用量与余额

套餐额度在实际 provider 预留事务中检查，覆盖 Agent、规划和验收等通过现有 Model Job 预算入口发送的模型请求。用量直接统计持久的 `provider_budget_reservations`，按 UTC 自然月，单位是物理请求尝试，不是建模任务或成功模型数；重试、未知发送结果和未发送释放的尝试也计入次数，与现有请求安全预算口径一致。同一逻辑请求恢复复用原预留，不额外计数。切换套餐只改变总上限，不清零当月用量。

套餐额度与原有 provider 请求/费用安全上限同时生效；提高套餐额度不会自动扩大既有 provider 授权。暂停、到期或耗尽时拒绝新预留，不删除已保存模型，不撤销已受理的预留或丢失恢复回执。服务身份沿用原有 provider 策略，不计入个人套餐。

客户余额与 provider 成本账本完全分离。客户余额只使用整数分，不能透支；当前唯一余额操作是平台管理员的 `admin_adjustment`。每笔操作必须包含幂等键、依据和说明，余额更新与不可改写的流水在同一个事务内提交。重复相同请求返回原结果；同一键改变金额或依据会拒绝。说明和依据会出现在用户流水中，不应填写密钥等内部信息。

后续接入充值时，需要新增经过签名验证及订单核对的支付回调和支付入账类型，以及明确的消费定价、退款与对账流程，不能把本阶段人工调账接口当作支付成功回调。

## 真实接口与发布约束

- 用户：`GET /api/billing/me`、`GET /api/billing/entries`（最近 100 笔）、`GET /api/billing/plans`。
- 平台管理员：`GET/POST /api/billing/admin/plans`；创建新的不可变套餐版本。
- 平台管理员：`PUT /api/billing/admin/tenants/{tenant_id}/subscription`；携带 `plan_version_id`、`expected_revision`、`idempotency_key`、`status` 和可选的带时区 `expires_at`。
- 平台管理员：`POST /api/billing/admin/tenants/{tenant_id}/adjustments`；携带整数 `amount_minor`、`idempotency_key`、`reference`、`reason`。

账号面板显示真实工作区套餐、余额和本月用量；加载失败显示错误，不填入虚构余额。账号或工作区变化时重建展示状态并取消旧请求。未配置支付时明确显示尚未开放充值和自动扣费。

先升级数据库，再启动新应用。有客户流水、套餐变更或新增套餐版本时，0033 禁止有损降级。腾讯云发布预检在检测到套餐配置或客户账务记录后，要求目标应用支持 `customer-billing.v1`，防止回滚到会绕过套餐准入的旧应用。该保护依赖使用当前的发布预检脚本。

验证入口：`tests/integration/test_customer_billing.py`、`test_session_revocation.py`，既有 provider 预算与数据库升级回归，以及真实浏览器 `tests/e2e/customer_billing_browser.py`。以上均使用隔离测试账户和数据库，不调用付费模型。
