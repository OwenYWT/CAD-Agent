## 已接入内容

| 工具 | 真实实现 | 边界 |
|---|---|---|
| `freecad_discover` | 查询固定 FreeCAD 发行版实测 API、命令、工作台目录 | 目录可发现不代表功能已验证 |
| `freecad_describe_operation` | 从运行时 Pydantic 契约按需返回操作参数 Schema | 不复制一份手写参数表 |
| `freecad_inspect` | 查询工作流持有的已验证原生文档检查点 | 未记录的几何明确不可用；不接受模型指定任意存储地址 |
| `freecad_execute` | 模型提交操作参数 → 严格校验 → 持久化源码 → Temporal CAD Activity → 真实 FreeCAD → 产物完整性检查 | 这是延迟执行的工具调用；规划阶段不会返回执行成功，不授予接受或提交权限 |

保留类型化操作与 `api.execute` 后台执行能力。生成和修复均通过同一工具协议。执行失败仍走已有结构化诊断、修复和重新验证；没有把失败改成固定成功，也没有增加模型输出上限或 CAD 等待截止时间。

模型适配层支持按索引拼接交错到达的函数调用、参数分片、调用 ID 与 usage；拒绝混合响应身份、缺失终止块及不完整调用身份。工具参数进入响应证据哈希，避免空 content 使不同工具请求产生同一个响应哈希。思考上下文仅用于模型协议往返，不展示为用户进度。

读取结果与错误均绑定原调用 ID。建模调用的 provider ID、参数哈希、持久化 source ID/hash 写入任务事件；真实执行回执绑定 source、attempt 和真实产物。回执明确工程验证仍待完成、没有已保存版本，后续独立检查和用户确认继续由现有工作流负责。

移除旧的三次状态检查查询预算，改为拒绝重复无新信息的同一查询；保留分页和单次结果体积约束。读取工具不提供 tenant、principal、存储 key 或 confirmed 参数。

## 本轮发现并处理的问题

1. 旧流式接收器明确拒绝 tool_calls，不能仅给模型增加工具描述。已补齐实际接收、校验及证据记录。
2. 真实 Kimi 首次请求返回 HTTP 400：思考模式与强制 `tool_choice=required` 不兼容。最小请求复现相同错误；改为 `auto`，保留思考模式，并保留下一轮工具消息所需的 reasoning_content。官方 K2.7 Code 示例同样使用 auto：[Kimi 官方文档](https://platform.kimi.ai/docs/guide/kimi-k2-7-code-quickstart)。
3. 首轮集成测试读取执行结果时错误地从 staging manifest 表取 result_payload。真实表结构将其保存在 execution_attempts；已修正测试 JOIN，四个用例重跑通过。
4. 架构检查发现执行层引用 CAD 工具实现会形成越层依赖。执行回执移至独立共享契约，没有放宽依赖方向或登记豁免。
5. 第二次真实 Kimi 运行完成几何生成，但没有函数调用分发事件，工具审计失败。根因是原系统提示和 next_response 仍要求输出旧 JSON，与新工具指令冲突。清理冲突指令后，第三次同一用例实际发出 tool_calls，通过工具审计、最终几何检查与提交。没有把仅生成模型视为工具链通过。
