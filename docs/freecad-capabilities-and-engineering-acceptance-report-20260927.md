# FreeCAD 能力开放与工程验收实施记录

状态：实施中。已实现通用调用及工程验收主链；不能据此宣称全部官方能力逐项验收、任意复杂场景可靠或三个目标全部完成。

产品口径澄清：本报告中的 API/GUI 指后台沙箱的执行方式，前端没有新增 FreeCAD 原生界面。用户要求的交付是对话驱动的 Agent 工具闭环；当前 FreeCAD 专用查询/操作计划尚未统一接入现有 Agent 工具注册体系，不能将本报告的底层执行验证称为这一产品目标已完成。后续以 [更新后的工具封装方案](freecad-complete-capability-and-verification-plan.md) 为准。

工作目录：`CAD-Agent-native-reliability`，分支 `fix/native-engineering-reliability`。本次未推送、未部署，线上服务未替换。保留本分支既有原生建模修复；本报告只归纳此次新增能力。

## 1. 已接入的能力

### FreeCAD 原生 API 与图形环境

- 保留类型化操作，新增 `api.execute`，由独立 FreeCAD 进程执行真实 Python API；支持无界面及 Xvfb 图形环境。
- API 程序得到实际文档、App、Part、Sketcher，图形模式提供 Gui。可导入镜像中实际存在的模块；缺少插件、依赖或图形环境时明确失败。
- 执行仍在无网络、只读运行时、无应用凭据和宿主控制接口的既有沙箱中。不是通过 Python 关键词过滤宣称安全。
- 由父进程重新打开 FCStd，执行文档校验、导出及状态投影；独立验证器重新测量 STEP。脚本自报成功、体积或尺寸不构成验收证据。
- API 计划必须显式声明最终导出对象；Part 布尔运算的 Base、Tool 等中间实体保留在文档中，但不会混入最终 STEP 和视口。
- 调用失败保留既有有效产物。没有新增模型输出长度限制或 API 执行时限。

### 可查询的能力目录

目录来自固定 FreeCAD 1.1.3 运行时的实际反射：24 个已导入模块、588 个顶层可调用项、457 个已注册命令、20 个工作台。Agent 可以分页查询模块/API 文档，也可查询命令及工作台名称，不必每次接收完整目录。

目录明确区分“可导入/已注册但未功能验证”；命令发现没有执行所有命令。嵌套 API、工作台激活后新增命令、插件与外部求解器不在“全部已验证”的承诺内。

### 工程需求契约与最终几何门槛

- 新的 3D FreeCAD 自然语言生成、修改任务携带版本化验收契约；记录来源原文、名义值、公差、基准和测量范围。
- 坐标支持世界坐标、包围盒中心和最小角点；模型不能把“居中”静默解释成自选世界坐标。
- 用户明确要求不得降级为可选；模型假设不得升级为必须要求；证据缺失、契约不匹配、必需项未验证均不能授权成功。
- 验证请求、契约摘要及实际产物摘要绑定，防止旧缓存或其他候选的报告被复用。
- 数值精度与工程公差分开处理，不使用统一百分比作为尺寸验收。
- 新字段缺省时保持旧序列化格式；工作流通过 Temporal patch 隔离新旧行为。

| 测量 | 实际方法与边界 |
|---|---|
| 实体数 | 最终 STEP 的真实实体数；独立零件与装配不采用同一默认值 |
| 外形、体积 | 指定轴上的实体范围、BRep 材料体积 |
| 孔数 | 凹圆柱/圆锥边界按同轴、相接区间归组；沉孔多段不重复计数 |
| 孔径 | 区分直孔段最小孔径与最大孔段/孔口尺寸 |
| 孔深 | 区分总凹入深度和直孔段长度 |
| 孔位置 | 在指定坐标基准及孔轴横截面中比较实际轴线位置 |
| 圆柱壁厚 | 完整轴向范围的同轴圆柱侧壁径向厚度；不代表端盖厚度 |
| 指定平面壁厚 | 指定平面、完整对面覆盖及中间材料体积核验；内部空腔不能被忽略 |
| 局部壁厚 | 显式点和方向上的材料区间；只证明该局部 |
| 空腔连通性 | 显式测量区域内的布尔差集与空腔分量；避免从外部空气绕行造成假连通 |

全局任意曲面法向壁厚仍返回未验证。非圆孔、开放圆柱边界、无法可靠匹配的复杂拓扑不伪造通过。

### 规划、修复与视觉判断

- 几何失败证据和原始验收契约一起传递给修复；不允许通过改验收目标解决建模错误。
- 对具备明确契约的切除修复，允许修正私有草图的位置，同时保护尺寸、共享依赖和明确锁定方向；旧历史保留原行为。
- 视觉判断只接收同候选、同产物、同契约的独立几何事实，避免把不可见的已测孔误判为缺失；局部测量不能冒充全局证明。
- 规划重试现在携带实际失败字段和校验原因，失败最终保留字段诊断；不再仅重发相同请求并返回笼统 ValueError。
- 实测暴露了“孔位置禁止标量 nominal，但对外 Schema 允许”的不一致。已把测量类型的条件规则加入发布 Schema，并用独立 JSON Schema 校验与运行时校验交叉测试；没有用固定返回值或放宽规则解决。
- 倒角/圆角的范围选择也补齐了 Schema 互斥规则：显式范围与旧版默认“全部边”不能同时成立。保留旧计划默认值以兼容历史；新接口明确要求选择范围时关闭全部边，拒绝冲突输入。

## 3. 尚未关闭的目标

1. 所有官方工作台、GUI 命令和 API 的逐项真实功能验收尚未完成；已开放调用通道不等于全部能力验证完成。
2. 当前主产物协议仍围绕 FCStd、STEP、STL、DXF 和实体建模；TechDraw PDF 等非实体产物、任意插件/求解器需要进一步接入完整发布链。
3. 任意曲面的连续法向壁厚、一般非圆孔、复杂拓扑映射，以及普遍的 FCStd 最终 Body Tip 与 STEP 一致性证明尚不完整。
4. 尚未新增可持久恢复的逐操作检查点；现有任务幂等、有效版本保留和失败回滚继续工作，但不等于复杂建模任意步骤恢复已完成。
5. 结构化手动参数修改和版本恢复仍使用原有门槛，尚未全部生成新的逐特征需求契约。
6. 自然语言要求的完整提取仍依赖模型；来源原文校验不能独立证明“没有漏要求”或“数值解释完全正确”。
7. 本轮没有重跑固定十题、P17/P32/P35 重复稳定性和扩展复杂集；不能用单条链路或大量单元测试替代复杂任务成功率。
8. 新验收契约尚无通用倒角尺寸/完整作用范围证书。真实修改规划已将该项列入 unresolved，不能删除它或仅靠 Hole 上游参数证明最终倒角正确。已有独立倒角几何测试通过，不等于该证明已接入所有自然语言任务。本轮不能发布为完整修复。

下一步的必要顺序：先补倒角最终几何证书与范围保护，再统一审计其余类型的 Schema/运行时差异；用已保留产物进行离线正反例核验，全部通过后再运行同一真实模型场景。不能通过切换为更简单的题目、删除 unresolved、关闭必需门槛来得到绿色报告。

真实调用成本：两次启用失败证据保留的运行共记录 12 次调用、93,858 tokens；更早运行未保留完整用量，不能将这个数字作为整轮总费用。发现倒角验收缺口后停止付费重跑，先完成可离线核验的回归。

可随代码复核的日志、浏览器结果及源码逐文件摘要已收录在 [验证证据目录](verification/freecad-capabilities-20260927/summary.json)。真实 Kimi 失败的 FCStd、STEP、原生状态和诊断保留在上述隔离证据根目录的 `work/live-evidence/`；临时付费凭据已从本轮运行配置清除。浏览器测试专用服务已停止，数据与报告保留。

后续按原实施方案继续：扩大能力逐项证据、补齐语义保护和检查点、完善复杂几何验收，再冻结版本进行同模型同题集对照。不得把上述未关闭项改写为“全部落地”。
