# FreeCAD 检查点、曲面验收与需求工具进展

工作区：`/Users/wentao/CAD-Agent-native-reliability`；分支：`fix/native-engineering-reliability`。本轮继续开发，未推送 GitHub、未部署腾讯云。原项目目录和原测试栈保留。

**三个目标仍未全部完成。** 本轮补齐了实际执行后返回 Agent 的检查点循环、可恢复 CAD Job、整面/整件材料层壁厚证明及需求契约工具。固定十题完整真实模型评测仅 2 题生成并保存；不能用单元测试数量、能力目录数量或需求解析通过数替代复杂建模成功率。

## 1. 本次实现

### Agent 观察、执行与继续建模

- `freecad_execute` 明确区分 `checkpoint` 与 `final`。中间步骤可保留草图/非实体 FCStd；最终步骤仍须满足请求的真实导出格式与独立验收。
- 真实执行完毕后，任务把已校验状态与执行回执交给 Agent，再决定查询、增量建模或修复。模型自行写出的“执行成功”不能推进检查点。
- 检查点绑定租户、工作流、候选、基础版本、源码哈希及产物 SHA/大小；Agent 不提供任意对象存储地址。恢复读取时再次校验身份与内容。
- 失败不推进游标；修复从上一个成功检查点继续。中间检查点禁止被当成最终候选提交。
- 完整检查点状态从持久化引用按需加载，避免每轮通过 Temporal 历史重复搬运；步骤索引按工作流在数据库锁内分配，避免多轮操作冲突。
- 旧发布历史通过 patch 分支兼容，没有重写旧历史。

### 长任务执行、取消与恢复

- CAD 执行、几何验证、渲染、DFM 与 BOM 经现有持久化 Job 调度；保留原有代次栅栏。
- 新 CAD Job 链路没有模型输出 token 上限或建模等待截止时间；取消由真实控制信号执行，不以缩短超时掩盖长任务。
- Docker 取消会移除实际容器并等待执行线程退出，处理取消与容器刚创建之间的竞争；Podman 的无截止等待同步支持。
- Worker 中断可恢复；用户取消、过期代次不能发布结果。通信故障保留真实类别，不一律显示超时。
- 租约、数据库事务、旧历史 Activity 和既有人工确认流程的超时仍存在；不能将其称为“整个系统没有任何超时”。本次移除的是新模型/CAD Job 的执行等待截止时间，旧历史中的计时行为保持回放兼容。

### 能力发现

从实际 FreeCAD 1.1.3 环境生成目录：24 个模块、5,257 个全限定可调用条目（包含类方法与继承别名）、342 个原生对象类型、457 个注册命令、20 个工作台。Agent 可按需发现、查询参数、检查文档并调用类型化操作或后台原生程序。

目录条目明确为导入/注册可见、尚未逐项功能认证；**这些数字不是已验证功能数**。通用后台桥接、图形运行环境与代表性调用已经存在，但不能据此宣称全部官方功能、插件、外部求解器和设备链路均已验收。用户入口仍是 AI Native CAD 对话。

### 独立曲面与壁厚验收

- 保留孔数、孔径、孔深、位置、实体数量、体积、区域空腔连通性等最终产物检查。
- `surface_clearance` 测完整裁剪 BRep 面之间的最小间隙；明确不等价于法向等壁厚或物理适配证书。
- `surface_normal` 对可证明的平面、球面、环面及一般裁剪曲面构造法向偏置材料层；核验完整对面边界、材料存在性及自交/实体有效性。
- `continuous_normal` 将可证明、非重叠的法向材料层与整个最终实体做覆盖比对；不能用局部点或区域冒充整件证明。
- 测量从实际几何推导厚度，不从用户期望值构造“测量答案”。隐蔽空腔、偏心内腔、变化厚度及未覆盖材料均有反例；无法证明时返回未验证。
- 真正的 FreeCAD Bezier 曲面偏置实体及其 STEP 已经过完整链路；2 mm 壁厚可通过，要求 3 mm 会被拒绝。
- 同一曲面存在真实 FDM 悬垂风险。制造门禁为必需时阻止候选；仅供参考时保留失败证据，接受候选仍需人填写风险审查意见。几何正确不等于可直接制造。

这是一套有适用域的材料层证明，**不是任意曲面、任意厚壁交汇结构的通用中轴厚度求解器**。不确定内核运算、无法唯一选面的情况不会强行判通过。

### 需求契约与真实模型暴露的问题

- 生成/修改需求改为 `submit_cad_plan` / `submit_modification_plan` 工具；工具参数来自实际契约，并以测量种类区分必须字段。
- 错误反馈携带准确字段及原工具调用 ID，支持模型修正；保留模型协议所需上下文，不展示冗长思考文本。
- 需求原文由服务端绑定；引用必须为原文连续片段。用户明确尺寸不可降级成可选，假设不可升级成强制验收。
- 修复了 `required` 的通用默认值问题：省略时由已声明来源决定，用户/已确认要求为强制，假设为可选；显式矛盾值仍报错。这不是按题号修正结果。
- 工具模式去掉与新契约冲突的旧 JSON 输出样例；旧 JSON 路径的完整提示保持不变。
- 用户没有提供制造公差时不凭空添加公差，也不因此阻止名义几何建模。新设计中的自由布局可以明确记为假设；实际配合所必需的未知尺寸仍需确认。
- `verification_limits` 区分验证器能力缺口与用户缺少输入。软件不会检查弯曲半径等条件时，应说明无法验证，不让用户通过回答问题来弥补软件能力。

测试失败记录没有删除：曾因测试读取错误异常包装、未实现受控修复接口、提交原封不动的修复计划，以及漏填制造风险审查意见失败。分别核对真实 Temporal/数据库后修正测试；没有去掉生产的无进展保护、工程门禁或审查要求。

完整服务回归还发现了实际代码兼容性缺陷：主机 Pydantic 为 2.12.5，后端镜像按项目依赖使用 2.7.0；后者在新增前置校验器后返回 JSON Schema 引用，直接访问 `properties` 会失败。主机单测无法覆盖这一差异。现改用公共 `resolve_ref_schema` 接口，先前失败的两条真实链路复跑通过；随后对修正后的冻结版本重新执行完整服务回归，并在真实后端依赖镜像中补跑全套无外部服务测试。新增的 jsonschema 是项目已声明的测试依赖，没有升级或替换生产 Pydantic 来绕过问题。

真实依赖单测进一步发现倒角/圆角工具 Schema 的相同引用问题：约束没有完整发布给模型，而执行校验仍然拒绝非法范围。统一修正后，完整参数目录与运行时契约再次一致，非法外边/全边混用反例会被 Schema 和实际模型校验共同拒绝。实际依赖单测初跑还受临时快照丢失脚本执行权限、只读挂载缺少测试数据目录影响；修复的是测试环境，未修改业务逻辑规避这些失败。CI 现有后端单测本来就安装 `requirements-dev.txt`，包含项目锁定的 Pydantic 和本轮新增 jsonschema 测试依赖。

版本口径：完整服务回归运行于 `validated-source`；其后仅倒角/圆角参数发布的两个 Schema 引用解析方法有差异，执行校验器和几何内核未变。最终 `current-source` 另有整套实际依赖单测及工具链补验。证据索引保存两者指纹与该差异，不将不同源码快照冒充同一次执行。

## 3. 真实 Kimi 评测：不能混合口径

### 检查点协议用例

真实 `kimi-k2.7-code` 查询能力后生成中间板材，读取已执行状态，再加中心通孔；通过真实 FreeCAD、独立几何、候选和提交。原生/STEP 独立复核：60×40×8 mm、一孔 Ø6、贯通、居中。

需求与视觉在此用例受控，只证明实际模型可使用检查点工具；不是完整自然语言端到端成功率。此用例数据库清理前未保留所有工具轮次总用量，不能把最终两次源码 provenance 的 token 相加称为全用量。

### 后续只复核需求，不重复整条付费建模

针对上述共性调整工具契约后，固定十题需求阶段整组复核，保留每轮，不选择最佳结果拼成成绩。首轮 7/10 生成合法契约，18 次调用、193,492 token；第二轮 9/10，13 次调用、194,012 token。第二轮 P03、P35、X04 仍含验证能力缺口，合法契约不算完成建模；P01 因省略假设的 `required` 触发错误。

首轮诊断脚本没有设置账号上下文，监控拒绝无身份归因；实际调用 provenance 保留。第二轮使用真实隔离账号并记录用量；数据库核对 13 次均有正确账号、完整 usage，token 总和与响应记录一致。生产 HTTP/工作流账号路径与监控权限另外验收，不把诊断脚本的无身份调用算作归因通过。

第二轮暴露的省略假设 `required` 问题已用实际保存响应离线复现并修复；旧 JSON 示例冲突也已移除。最终解析器对该轮十份保存响应的离线重放均通过，但这不是新一轮模型运行。没有为了追求高分再付费反复跑失败题。最终版本尚未重跑完整十题建模，应明确保留这项未验证状态。

## 4. 仍未完成的目标

1. 官方全部 FreeCAD 功能逐项依赖、调用与最终结果认证；目录、通用桥接和代表性用例不能替代。第三方插件也不能未列清单就声称全部支持。
2. 任意复杂曲面/厚壁交汇结构的全局厚度证明；当前只对材料层覆盖可证明的情况通过。
3. 弯曲半径、螺纹规范、任意倒角尺寸/范围、任意装配配合与制造条件的通用验收。
4. 自然语言到验收契约的完整语义覆盖与稳定性。合法 Schema 并不能证明模型没有漏掉某条需求；更复杂题集、多次真实运行仍必要。
5. 工程测量、任务控制、用户审查及导出全部作为独立可调用模型函数工具；目前部分职责继续由已有工作流与产品服务承接。
6. 最新版本完整真实模型十题与扩展复杂集成功率、完整云部署升级/回退。从已有运行时覆盖构建测试镜像成功，但未证明当前平台从零构建 FreeCAD AppImage 镜像成功。

发布判断：目前有可复查的能力进展和失败保护，但没有证据宣布“全部 FreeCAD 能力开放且复杂任务可靠”已经完成。
