# FreeCAD 能力开放、复杂任务可靠性与工程验收实施方案

状态：实施中。Agent 工具已支持实际执行后的文档观察、持久化检查点与继续建模；独立验收已增加整面及整件的法向材料层证明，不能证明的复杂曲面仍明确未验证。官方全部功能逐项认证、复杂任务成功率和云端发布验收尚未闭合。最新证据见 [检查点与曲面验收报告](freecad-checkpoints-and-curved-acceptance-report-20260929.md)，此前报告保留为历史记录。
基线：当前 `fix/native-engineering-reliability` 工作树；保留本轮修复及完整十题评测。

## 产品边界与 Agent 工具封装（用户最新澄清）

产品是 AI Native CAD。用户通过对话提出需求、补充条件、确认或拒绝修改，并获得模型、变化摘要和工程检查结果。FreeCAD 不成为用户直接操作的产品入口。API、Python、工作台和虚拟显示环境全部是工具内部的执行细节；需要图形环境的能力也由后台工具承接，不要求用户打开 FreeCAD 或编写脚本。

2026-09-28 更新：`app/freecad/operation_generator.py` 已向模型发布四个函数工具：`freecad_discover`、`freecad_describe_operation`、`freecad_inspect`、`freecad_execute`。读取结果以匹配调用 ID 的 tool 消息返回；执行请求经过既有生成源码持久化、Temporal 执行、独立验证和候选机制。旧 JSON 输出继续兼容。`app/api/agent_tools.py` 仍只加载 Onshape，同步插件接口没有获得绕过持久化任务的 FreeCAD 写入入口。当前是工作流内的 CAD 工具协议；尚不是所有工具职责或逐操作检查点闭环全部完成。新增证据见 [工具接入报告](freecad-agent-tools-report-20260928.md)。

目标链路：用户对话 → Agent 理解与规划 → 版本化 CAD 工具接口 → 既有持久化工作流和隔离 FreeCAD 执行器 → 独立验收 → 结构化工具结果回到 Agent → 继续操作、修复或向用户询问关键缺项。

2026-09-29 更新：四个 Agent 工具继续复用同一协议；`freecad_execute` 增加中间检查点/最终产物的明确区分。真实执行结果持久化后返回 Agent，后续操作从已验证检查点继续；CAD 执行改用可恢复的持久化 Job，不设置建模等待截止时间。最终几何与工程门禁仍独立执行，检查点不能作为最终候选提交。通用工程测量、任务控制、审查与导出尚未全部注册为独立模型函数工具，不能据此称全部职责完成。

以下为目标工具职责，不代表这些工具现已全部注册或测试通过：

| 工具职责 | Agent 输入/输出 | 复用与约束 |
|---|---|---|
| 能力发现 | 按任务查询可用能力、参数、依赖及验证状态 | 复用实测目录，按需加载，不一次发送全部接口 |
| 文档检查 | 基于明确版本读取对象、参数、拓扑、依赖和已有检查证据 | 复用已校验原生状态，不能凭名称猜对象 |
| 建模与修改 | 提交结构化操作或受控原生执行程序，返回任务身份、候选及对象变化 | 复用工作流、沙箱、幂等与代次栅栏；不会直接覆盖已保存版本 |
| 工程测量 | 对指定候选的最终产物测孔、壁厚、位置和连通性等 | 复用独立验收，必需门槛由服务端执行，Agent 不能自行取消或伪造证据 |
| 任务控制 | 查询进度、读取失败原因、取消及从支持的检查点恢复 | 长任务沿用持久化机制；不套用同步工具的固定执行时限 |
| 候选审查 | 展示差异，按用户明确决定接受、拒绝或继续修改 | 复用权限与版本冲突检查；模型自己生成 confirmed 不等于用户授权 |
| 导出 | 从明确版本取得真实产物与下载信息 | 复用已有产物和权限体系，不返回占位链接 |

工具结果必须包含任务/候选/版本身份、实际状态、对象变化、产物或证据引用，以及结构化失败原因。Agent 应能根据一次调用的实际结果决定下一次调用；只有“生成整段脚本后统一执行”不足以证明复杂任务的观察与修复闭环。

实施时保留现有有效的底层执行和验收工作，补齐工具定义、注册、服务端身份绑定和 Agent 调度。验收必须从真实对话触发，记录模型实际选择的工具及参数，经过真实内核和独立测量，最终形成用户可确认的候选。仅有工具目录、手工调用 API、受控规划测试或桌面 GUI 演示都不算完成该目标。

## 三个目标及完成定义

1. 能力开放：对固定版本的官方能力建立逐项清单，提供可发现、可调用、可解释失败的实际入口。第三方工作台按已确认清单和版本纳入；图形依赖显式标注并由对应执行环境承接。不以一个任意 Python 入口等同全部能力已验收。
2. 复杂场景可靠：需求、几何、检查与修复使用同一份需求依据；任务可恢复、可取消、不覆盖有效版本。可靠性通过固定分层测试集、多个参数变体和重复真实模型运行衡量；不承诺任意复杂任务必然成功。
3. 工程验收：孔数、孔径、孔深、位置、壁厚、连通性等有独立最终产物证据。必需项目未验证时不能标记工程验收通过；可保留明确标识的未验证候选，不能静默降级标准。

## 实施前核对的事实（历史基线，非当前完成状态）

- 实际沙箱 FreeCAD 1.1.3；本次只读探测 `GuiUp=false`。
- 镜像有 Assembly、BIM、CAM、Draft、Fem、Import、Inspection、Material、Measure、Mesh、OpenSCAD、Part、PartDesign、Points、ReverseEngineering、Robot、Sketcher、Spreadsheet、Start、Surface、TechDraw、Test 模块目录。目录存在仅表示打包了文件，不证明加载、依赖、调用或功能测试通过。
- 原生协议只开放 20 类操作；这不是 FreeCAD 全能力清单。
- 现有 Temporal、任务代次栅栏、沙箱、对象存储、版本、候选审核与 UI 继续复用。
- 验证契约已有孔径/孔深/壁厚等类型，但通用 evaluator 对多数类型返回 indeterminate。
- 当前工作流构造 verification_evidence 后仍依据 geometry.outcome 判断后续，不是所有必需特征都约束最终通过。
- 目标类型部分通过英文关键词推断，未知名称默认落入 overall_dimension，可能将中文壁厚误当包围盒。不能继续扩展关键词表作为主要工程契约。
- 实测 P18 原生 Body Tip 及 STEP 含两个实体，最短距离 1 mm；旧评分判通过。P17 有需求假设与视觉判断冲突；P32/P35 仍有失败。

## 目标架构

用户需求 → 有来源、版本化的需求契约 → Agent 查询能力和模型状态 → 执行计划
→ 无界面原生/API执行或有图形环境的工作台执行 → 候选检查点
→ 独立几何验收 + 视觉辅助检查 → 局部修复 / 等待澄清 / 可接受候选 → 明确提交。

模型不能更改其自身验收依据。新旧执行路径共享任务身份、基础版本、产物协议和验收门槛。

### 能力层

- 保留现有类型化操作，作为常见能力的稳定路径。
- 增加通用 FreeCAD Python API 执行桥接，以覆盖逐项包装之外的功能；继续在无凭据、无宿主控制接口的隔离运行环境执行。
- 对依赖 Gui、选择状态或交互命令的能力增加图形运行环境及命令适配，处理文档、选择、编辑和对话框状态，不将导入模块成功当成调用成功。
- 能力发现来自固定发行版的模块、公开 API、命令和运行探测；AI 按需检索接口说明与示例，避免每次发送整个 API 目录。
- 每项能力记录：版本、接口、依赖、执行环境、输入/输出、前置条件、实际验证证据、已知限制。区分未安装、不可用、可调用未验证、已验证。
- 插件按指定清单安装和验证；求解器、加工设备及外部服务依赖单独声明。
- 通用代码不能伪造验收结果：候选产物由独立验证过程重新打开测量，不能信任脚本自报成功或体积。

### 需求与验收契约

- 每项要求包含对象/范围、单位、名义值、允许偏差、基准坐标、来源、必需程度、需求版本。
- 区分用户明确值、经确认默认值、待确认值、计算派生值。缺失依据不凭空写入强制验收标准。
- 有争议的内外侧、法向/径向壁厚、外翻唇边是否计入外形等，在建模前整理为可核验的定义。
- 数值计算容差、工程公差和测量不确定度分开记录；不使用统一 10% 标准。
- 新契约用于新任务，旧历史保持可回放；旧产物没有证据的字段明确未验证。

### 独立几何验证

- 以最终 Body Tip、导出的 STEP 及二者一致性为证据；不以模型计划、特征命名或中间 Hole 参数代替实际几何。
- 孔：按实际空腔/边界和轴线分组，区分一个孔的多个圆柱面、沉孔段、盲孔和通孔。计数、直径、轴向深度、位置、孔距、边距使用明确基准。
- 壁厚：平面、圆柱等解析情形先精确测量；复杂曲面使用明确适用域和误差的算法。不能由两端径向差声称整段法向等厚；采样结果必须记录覆盖范围。
- 连通性：一体零件要求对应的实体连接关系；装配按零件清单和连接意图检查，不把所有装配强行要求单实体。
- 倒角/圆角及受保护区域：核验最终加工范围，修改前后比较受保护尺寸和几何。
- 每条结果输出目标版本、对象、方法、实测值、预期值、偏差、单位和证据摘要。
- 必需项目失败或未验证不得标记工程验收通过。视觉检查只负责可观察形态；截图无法量尺寸不自动等同尺寸失败。

### 复杂任务的执行与修复

- 分解为可核验步骤和检查点；每步保留有效文档、对象身份、依赖、输入和结果。
- 从有效检查点恢复，失败局部回滚；最终提交仍遵守现有版本冲突和代次栅栏。
- 错误分为契约、引用/坐标、约束、内核几何、需求不一致、验证不足、依赖/服务故障等。
- 修复保护的是需求和未请求区域，不把所有失败固定为只能改某一个字段。例如无效切除先核对位置、相交关系、方向与路径，再选择符合需求的修复。
- 草图区分独立驱动尺寸与派生尺寸；发现冗余先验证等价性，不按错误编号盲删约束。
- 同一状态、同一计划、同一失败无进展时停止无意义循环并保留诊断。任务长耗时显示进度、支持取消和恢复，不通过缩短超时或限制模型输出来掩盖问题。

## 依赖顺序及阶段验收

| 阶段 | 交付 | 必需测试与证据 |
|---|---|---|
| 0 | 冻结源码/镜像/题集，形成官方能力与运行环境清单 | 能力发现一致性、真实依赖探测；区分目录存在与已验证 |
| 1 | 需求契约、独立验证接口和最终接受/提交门槛 | 正例/负例/证据缺失、旧任务兼容；P18 最终实体反例必须被拒绝工程通过 |
| 2 | 孔、位置、厚度、连通性测量 | 参数变化、旋转/平移、沉孔多面、贯穿与盲孔、装配、相切/断开、导出一致性 |
| 3 | 通用 API 执行、能力检索和统一产物协议 | 真实缺失能力代表用例、失败回滚、篡改验收反例、旧20类回归；不把代表用例宣称全能力验收 |
| 4 | 检查点执行、语义保护及证据驱动修复 | P17/P32/P35 原始失败、修改保真、断线/取消/恢复、重试幂等、版本冲突完整链路 |
| 5 | 图形工作台及指定插件接入 | 按冻结清单逐项真实调用、参数/依赖负例、输出核验；未通过项保留未完成 |
| 6 | 整体回归与真实模型评测 | 模块/几何→API/Temporal/数据库→浏览器→固定十题新旧双评分→扩展复杂集及重复运行 |

## 评测口径与成本

- 保留旧十题评分作为历史对照；新增严格工程评分，不覆盖历史结果。
- 补充跨特征组合、尺度变化、坐标旋转、非对称几何、拓扑变化和局部修改，不能只扩大同类简单题数量。
- 先对已有最终产物离线复核，再用确定性几何与历史计划测试执行/验证，最后冻结版本批量调用真实模型。
- 预先确定题集和重复次数；报告首次通过、修复后通过、未验证、假通过、重复稳定性、耗时及 token。不得挑选最好一轮。
- 完成标准是固定范围逐项证据闭合。尚未明确复杂任务可接受的数值成功率，不能自行声称可靠性达标。

## 待明确的范围

以固定版本官方能力为完整目标，第三方工作台按明确清单纳入。用户已明确所有能力应封装为 Agent 工具，用户交互由对话承担；图形依赖属于后台工具实现，不是另设 FreeCAD 用户界面的理由。第三方插件清单尚未明确，不应声称全能力完成。
