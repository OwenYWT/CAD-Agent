问题及根因

API 子进程通过 FCStd 文件名保持文档身份，这项既有修复需要保留。
错误出在宏生成：先把文档路径填入 BEFORE，再对整个结果连续替换 GUI、MODULES、
AFTER 等普通字符串，已插入路径里的同名字符被再次解释成占位符。
因此 GUIBracket 被改成 FalseBracket.FCStd，部分名称还会破坏 Python 语法。
同一个真实 FreeCAD 1.1.4 内核、同一组输入，在改动宏生成前后得出不同结果，
说明此次缺陷位于项目的模板渲染层。

修改范围

1. backend/sandbox/freecad_api.py：复用标准库 string.Template，一次性填入参数；
   路径和模块列表仍用 repr 转成 Python 字面量，填入值不再参加后续替换。
   保留文档身份、子进程退出码、调用标识、状态文件、父进程重新打开与验收逻辑。
2. backend/tests/e2e/freecad_api_contract.py：扩展现有原生用例，覆盖 11 种名称，
   包括全部原占位符及组合；各自在 headless/GUI 环境新建、导出、继续编辑，
   共 22 次新建和 22 次继续编辑，重读 STEP 检查体积及原 FCStd 字节不变。
   原有表达式、布尔操作、错误程序、缺失导出对象和文档替换反例均保留。
3. backend/tests/integration/test_temporal_mcadd_workflow.py：复用既有 API 夹具和
   工程验收测试，增加组合名称的正反例，覆盖实际 Temporal、FreeCAD、S3、数据库、
   审核与提交；正例目标孔径 6 mm，反例要求 7 mm 而实际仍为 6 mm。
4. docs/architecture/ci-tests.json：为这两个服务用例登记 backend、外部服务跳过
   声明与 durable-core；验收期间补齐的三个既有用例仍在登记中。

本轮是在既有 22 个已修改文件的基础上继续开发，仅上述四个文件增加改动。
其他 18 个既有修改文件逐字节保持不变，既存未跟踪 QA 文件全部保留。
