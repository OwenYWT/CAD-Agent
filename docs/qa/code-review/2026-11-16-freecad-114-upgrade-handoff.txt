改动位置

1. backend/sandbox/Dockerfile、runtime-lock.json：锁定官方 1.1.4 的 ARM64/AMD64
   AppImage 与对应 SHA256。其余依赖版本不变。

   backend/app/execution/podman_backend.py：构建检查与真实运行时探测对应 1.1.4；
   使用旧 1.1.3 镜像会被明确拒绝，不能只修改版本显示冒充升级。
3. backend/app/freecad/api_catalog.json、api_catalog.py、operation_generator.py：
   从新镜像真实 GUI 环境重新发现 API，并同步查询检查与模型所见运行时版本。
   目录由 5,257 个符号变为 5,258 个，新增 TechDraw.scrubEdges，没有移除原有条目。
   发现目录不等同于逐项功能验收；functional_coverage 标记保持不变。
4. backend/app/freecad/bom_contracts.py：读取真实 1.1.4 BOM，同时继续接受已保存的
   1.1.3 BOM；保留原始版本来源和 Assembly::BomObject 检查。
5. backend/tests/test_freecad_bom_contracts.py、test_runtime_manifest.py：增加新旧 BOM
   读取覆盖，更新官方二进制锁定检查。新版本 BOM 用例修改前失败，修改后通过。
6. docs/architecture/ci-tests.json：登记版本测试改名，以及此前 BLG 补丁新增的三个
   集成用例；单元阶段按既有规则声明外部服务跳过，真实服务阶段仍要求执行。
7. deploy/tencent/README.md：明确增量沙箱 Dockerfile 只复制脚本，不能升级 FreeCAD
   二进制；发布 1.1.4 必须使用经过验证的新运行时基础镜像，并重新生成 API 目录。

测试环境问题与边界

初次服务运行遇到 MinIO RequestTimeTooSkewed；时钟重新核对一致后，真实对象
存储读写删除预检通过。随后 AMD64 大镜像提交层曾短时占满本地 VM 磁盘，导致
一项复测 XMinioStorageFull；失败构建自动清理后空间恢复，未清理其他服务/数据。
已停止大镜像构建，AMD64 核验改为挂载主机目录与独立 terminfo 测试卷。
本机 Rosetta 不支持官方 AMD64 AppImage 的静态启动壳，使用校验后的 SquashFS
提取；大小写敏感 terminfo 子树保留在 Linux 卷。AMD64 GUI 默认 LLVM 渲染失败，
临时测试环境 GALLIUM_DRIVER=softpipe 下同一完整 API 用例通过，未修改业务代码。
Mesa 官方参数说明：https://docs.mesa3d.org/envvars.html#gallium-driver

腾讯云只做了只读检查：磁盘仅约 689 MB 可用，现有沙箱约 8 GB；没有执行清理、
构建或发布。线上仍未升级，后续部署需具备足够磁盘并完成 AMD64 发布镜像验证。
本轮没有重跑真实付费模型，因此不声称模型成功率提升，也不声称升级自动解决
两条 BLG 历史任务中的全部建模问题。
服务回归采用现有可控规划/模型输入；FreeCAD、数据库、Temporal 与对象存储均为
实际运行。上述控制输入仅属于测试，未为业务链路增加 Mock 或固定成功路径。
