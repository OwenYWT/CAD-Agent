# FreeCAD 约束诊断与修复链路验收

日期：2026-09-19。对应原任务：`1f02f205-87ff-4e6f-98b7-a991e0197bd7`。

## 结论与根因

本次不是单独删除“第 25 条约束”。原任务触发了草图生成错误，同时暴露了错误回传、分类和修复链路的共性缺口。

| 环节 | 实际证据 | 本次修改 |
| --- | --- | --- |
| 操作生成 | 两个矩形各自已由尺寸与几何关系完全约束，之后又增加宽度相等、高度相等两条关系 | 提示约束独立性；保留真实求解与失败检查，不能靠提示词宣称有效 |
| FreeCAD 结果传输 | 原计划输出中 `(53 %)` 与 JSON 出现在同一行，逐行 JSON 解析失败，把真实草图错误变成 `sandbox_protocol_error` | 原子写入独立结果文件，绑定本次调用标识；日志不再充当结果协议 |
| 原生诊断 | 通用对象无效检查先于草图诊断；真实冲突实验返回 `-4`，原代码按 `-3` 判断冲突 | 使用求解器提供的冗余、冲突约束集合与自由度；先检查草图，再检查依赖对象 |
| 错误传递 | Activity、Workflow 向修复器传递时丢失操作、动作和诊断详情 | 保留 `operation_id`、`action`、`details`、`evidence` |
| 修复策略 | validation 类别未允许三类草图错误进入修复 | 明确区分冗余、冲突、欠约束；协议、资源和基础设施错误仍不能通过改模型处理 |
| 修复边界 | 原修复器只验证返回计划有效且与旧计划不同 | 三类约束修复保护已有数值约束、几何、建模操作、导出及其他草图；欠约束只允许增加缺项 |
| 防循环 | 不同操作可能返回同样的草图名称和约束编号 | 将实际报错操作纳入重复错误识别；仍保留重复失败和原有修复次数保护 |

生产代码没有电子盒、特定尺寸、任务 ID 或“第 25 条约束”的专用处理。编号只作为原生诊断证据传递，明确为一基编号，不直接变成删除命令。正常参数修改及历史版本恢复仍禁止 AI 擅自重写用户明确提交的修改。

本次没有增加或收紧模型输出 Token 限额、模型等待时限，也没有通过减少特征或改变尺寸让案例通过。原有 CAD 沙箱资源策略不在本次修改范围。
